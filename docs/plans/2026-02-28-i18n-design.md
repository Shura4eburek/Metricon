# Multilingual Support (i18n) Design

**Date:** 2026-02-28

## Goal

Add RU / EN / UA language switching via flag buttons in the navbar, with preference saved in localStorage. No server changes.

## Approach

Client-side JS i18n: one `static/js/i18n.js` file with translation dictionaries for all three languages. HTML elements get `data-i18n="key"` attributes; JS replaces their text on load and on language switch. JS strings (confirm dialogs, alerts, uptime units) use `I18N.t('key')`.

## Components

### `static/js/i18n.js`

Exposes `window.I18N` with:
- `TRANSLATIONS` — nested dict `{ en: {key: str}, ru: {key: str}, ua: {key: str} }`
- `currentLang()` — reads `localStorage('metricon_lang')`, fallback `'en'`
- `t(key)` — returns translation for current lang, fallback to `en`
- `applyLang(lang)` — sets localStorage, updates all `[data-i18n]` elements, updates flag button active state

Translation keys cover:
- Navigation: `nav.overview`, `nav.api_keys`
- Overview page: headings, column headers, empty state, toggle titles, status badges
- API Keys page: headings, table headers, modal labels, button titles, confirm/alert strings
- Bot Detail page: stat tile labels, chart headers, error table headers, empty state
- Uptime units: `uptime.d`, `uptime.h`, `uptime.m`, `uptime.less1m`

### `base.html`

- Add `<script src="/static/js/i18n.js">` in `<head>` (before page scripts)
- Add flag buttons to navbar: 🇷🇺 🇬🇧 🇺🇦 with `onclick="I18N.applyLang('ru')"` etc.
- Call `I18N.applyLang(I18N.currentLang())` at end of `<body>` to restore saved language

### Templates (all 4)

Replace hardcoded visible strings with `data-i18n="key"` attributes:
- Static text nodes → `<span data-i18n="key">fallback</span>` or attribute on existing element
- `title=` attributes → `data-i18n-title="key"` + JS sets `.title`
- JS inline strings (confirm, alert) → `I18N.t('key')`
- Uptime JS functions → use `I18N.t('uptime.d')` etc. instead of hardcoded `'д'`
